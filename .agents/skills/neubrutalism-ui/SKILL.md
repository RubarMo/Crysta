# Neubrutalism UI — The Definitive Design System Guide & Skill

A comprehensive, authoritative reference and production-grade design system for modern web and desktop applications. Built on the official foundations of Neubrutalism: **graphic bluntness**, **explicit structure**, **unblurred hard shadows**, **0px corner radius**, **bold quad-stack typography**, and **satisfying physical micro-interactions**.

---

## 1. Core Philosophy & "The One Rule"

> [!IMPORTANT]
> **The One Rule**: Start with a standard, conventional UX skeleton, then wrap it in neubrutalist tokens. Use predictable navigation, standard information architecture, and clear system-status feedback before applying visual aggression. Neubrutalism is a high-contrast theme layer on top of a conventional interaction model, **never** permission to abandon usability standards.

Neubrutalism translates anti-design energy into a repeatable, productized interface grammar:
- **Explicitness over subtlety**: Edges, containers, and interactive boundaries declare their presence.
- **Personality over invisibility**: Interfaces feel crafted by humans, not generated by an average-of-everything algorithm.
- **Memorable structure over soft cosmetic polish**: High contrast, crisp ink borders, and physical depth.
- **Categorical color, not ambient gradients**: Colors carve surfaces into obvious objects.

## 2. The 6 Non-Negotiable Invariants

### Invariant 1: Zero Border Radii (`0px`) Everywhere
- **Every interactive element, card, container, and UI primitive MUST have `border-radius: 0px`**.
- This applies strictly to: buttons, cards, modals, dropdowns, inputs, selects, textareas, badges, tags, slider tracks/thumbs, status pips, toasts, tooltips, tabs, and scrollbars.
- **Prohibited**: `rounded`, `rounded-sm`, `rounded-md`, `rounded-lg`, `rounded-xl`, `rounded-2xl`, `rounded-full`.

### Invariant 2: Heavy Black Ink Outlines
- **Default Components & Cards**: `3px solid var(--border-ink)` (or Tailwind `border-3 border-[var(--border-ink)]` / `border-black`).
- **Subtle Dividers & Badges & Small Controls**: `2px solid var(--border-ink)`.
- **Hero Containers & Modal Dialogs**: `4px solid var(--border-ink)`.
- Stroke width is a design token; outline clarifies the object and restores edge clarity.

### Invariant 3: Anti-Naturalistic Hard Offset Shadows (Zero Blur Always)
- Shadows represent physical layers misregistered or stamped down. Blur is **always 0px**.
- **Three-Tier Shadow Scale**:
  - **Small (`3px 3px 0 0 [color]`)**: Badges, chips, small controls, inline actions, segment buttons.
  - **Medium (`5px 5px 0 0 [color]`)**: Cards, primary buttons, input fields on focus, content panels.
  - **Large (`8px 8px 0 0 [color]`)**: Hover states, dropdown menus, floating action panels.
  - **Extra Large (`12px 12px 0 0 [color]`)**: Hero elements, modal dialogs, lightbox overlays.
- **Shadow Color Rules**:
  - In **Light Mode**: `--shadow-ink: #000000;` (harsh solid black ink shadow).
  - In **Dark Mode**: `--shadow-ink: rgba(255, 255, 255, 0.14);` (light tactile offset shadow to maintain physical depth against dark surfaces).

### Invariant 4: Strict High-Contrast Color Invariant (Solid Black Text on Color)
- **100% Solid Black Text Rule**: Any element with a colored background fill (**Bold Yellow `#FFD23F`**, **Coral Pink `#FF6B6B`**, **Sky Blue `#74B9FF`**, **Soft Mint `#88D498`**, **Lavender `#B8A9FA`**, **Orange `#FFA552`**) MUST HAVE **SOLID BLACK TEXT & ICONS (`color: #000000; font-weight: 700 / 800 / 900;`)**.
- **No Monochromatic Hue-on-Hue**: NEVER use dark navy text on blue, dark green on mint, or dark brown on yellow.
- **No Murky Translucent Fills in Dark Mode**: Stat cards and action pills remain solid and vibrant in both light and dark mode.

### Invariant 5: Neutral Balanced Dark Mode (Zero Blue Tint)
- Dark mode surfaces must use neutral graphite / zinc tones (`#1E1E22` canvas, `#26262B` surface, `#2D2D33` raised surface).
- Never use murky blue-grey or slate-tinted canvas.

### Invariant 6: Physical Press Micro-Interactions
- Interactive elements sink physically on click/press and lift on hover:
  ```css
  /* Hover: lift up-left + expand shadow */
  .nb-interactive:hover {
    transform: translate(-2px, -2px);
    box-shadow: 7px 7px 0 0 var(--shadow-ink);
  }
  /* Active / Press: depress down-right + kill shadow */
  .nb-interactive:active {
    transform: translate(3px, 3px);
    box-shadow: none;
  }
  ```

## 3. The 4-Tier Typography System

Neubrutalism pairs expressive high-contrast display headlines with calm, readable body copy:

| Role | Font Family | Recommended Weights | Purpose |
| :--- | :--- | :--- | :--- |
| **Display** | `Syne` (or `Bebas Neue`, `Archivo Black`) | `800`, `700` | Oversized hero headlines, landing statements, poster weight. Tight tracking. |
| **Heading** | `Space Grotesk` (or `Plus Jakarta Sans`, `Outfit`) | `600`, `700` | Section headers, card titles, navigation items, modal headers. |
| **Body** | `Inter` (or `DM Sans`, `Plus Jakarta Sans`) | `400`, `500` | Operational body copy. "Boring on purpose", generous line-height, standard spacing. |
| **Monospace** | `Space Mono` (or `JetBrains Mono`) | `400`, `700` | Code blocks, page numbers, counters, tokens, badges, technical labels. |
| **Arabic** | `Dubai`, `Cairo`, `Amiri` | `600`, `700`, `800` | Multilingual display and operational reading. |

```css
:root {
  --font-display: 'Syne', 'Space Grotesk', system-ui, sans-serif;
  --font-heading: 'Space Grotesk', 'Plus Jakarta Sans', system-ui, sans-serif;
  --font-sans: 'Inter', system-ui, sans-serif;
  --font-arabic: 'Dubai', 'Cairo', 'Amiri', system-ui, sans-serif;
  --font-mono: 'Space Mono', 'JetBrains Mono', monospace;
}
```

## 6. Accessibility & WCAG 2.2 Standards

| Criterion | Requirement | Neubrutalism Implementation |
| :--- | :--- | :--- |
| **1.4.3 Contrast (Min)** | 4.5:1 for normal text, 3:1 for large text | **Mandatory 100% black text (`#000000`)** on all bright pop fills (Yellow, Coral, Mint, Sky). |
| **1.4.11 Non-text Contrast** | 3:1 for UI boundaries | 3px/2px solid ink outlines provide >15:1 boundary contrast vs canvas. |
| **2.4.7 Focus Visible** | Clear keyboard focus indicator | `:focus-visible { outline: 3px solid var(--pastel-sky); outline-offset: 3px; }` |
| **2.5.8 Target Size** | Minimum 24×24px (44×44px touch) | Generous padding ensures all clickable controls meet or exceed target size. |
| **1.4.1 Use of Color** | Color not sole channel | Always pair color fills with text labels, icons, or square indicator pips. |

## 7. Anti-Patterns & Prohibited Mistakes

| Anti-Pattern | Correct Neubrutalist Pattern |
| :--- | :--- |
| ❌ `rounded-md`, `rounded-full`, `rounded-2xl` | ✅ `border-radius: 0px !important;` on all elements |
| ❌ Blurred drop shadows (`shadow-lg`, `shadow-md`) | ✅ Hard offset unblurred shadows (`shadow-[5px_5px_0px_var(--shadow-ink)]`) |
| ❌ Dark text on matching light background | ✅ Solid pure black (`text-black font-bold`) on all colored cards |
| ❌ Translucent / muddy card fills in dark mode | ✅ Solid saturated fills (Sky `#74B9FF`, Mint `#88D498`, Yellow `#FFD23F`, Lavender `#B8A9FA`) |
| ❌ Blue-tinted canvas in dark mode | ✅ Neutral graphite / zinc dark canvas (`#1E1E22` / `#26262B`) |
| ❌ Invisible black shadows in dark mode | ✅ Light tactile offset shadows (`rgba(255, 255, 255, 0.14)`) |
| ❌ Dotted paper pattern across headers & sidebars | ✅ Dotted pattern isolated strictly to the main scrollable canvas |
| ❌ White text on bright yellow or accent buttons | ✅ Always solid black text (`text-black font-black`) |
| ❌ Lonely floating icon box vertically stacked over card title (AI-slop layout) | ✅ Pair icon badges horizontally beside titles in a structured header unit (`flex items-center gap-3`) |
| ❌ Fake/redundant decorative filler badges (`EST. YEAR`, marketing tags) | ✅ Badges must strictly represent real, functional application state (`Completed`, `Page 14/120`) |
| ❌ Robotic buzzword-soup titles & subtitles (*"Virtual PDF Chunking & Batch Setup"*, *"Compile OpenXML (.docx) with embedded Arabic typography"*) | ✅ Ultra-concise titles (1–3 words, e.g. `Batch Setup`, `Export Book`) and clean 1-sentence human descriptions (*"Export your transcribed book to Word or EPUB"*) |
| ❌ Static/un-clickable marketing feature pills in app workspaces | ✅ Workspace screens should strictly present actionable controls; keep screens clutter-free |
| ❌ Desynchronized `dir="rtl"` / `dir="ltr"` between mobile menus and desktop switchers | ✅ Bind `document.documentElement` direction to `i18n.on('languageChanged')` reactively so all switchers flip direction automatically |
